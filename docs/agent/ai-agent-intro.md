打开 B 站搜“AI Agent”，你大概率会看到 Coze、Dify、LangChain、LangGraph、MCP、RAG、多智能体，还有各种“七天转行”和“从零到企业级”。课程没少收藏，真正的问题反而是第一步该做什么。时间很容易耗在换框架、比模型、看别人演示上，最后连一次完整的工具调用都没有跑通。

这篇不是课程目录，也不是框架 API 速查。它想解决一个更前面的问题：不知道编程、目标岗位和已有基础的新手与转行者，应该按什么顺序进入 Agent，哪些东西可以先跳过，学到什么程度才算真的入门。

## 快速认识

Agent 的最小判断标准不是“会聊天”，而是它能否围绕一个目标，在程序允许的边界内选择下一步动作，读取动作结果，再决定继续还是停止。

一条最小执行链通常是这样：

```text
目标 -> 模型决定下一步 -> 调用工具 -> 读取结果
     -> 更新状态 -> 继续或停止
```

“模型决定下一步”不等于模型拥有无限权限。真正执行工具的是程序，模型只是产生调用意图和参数。参数会不会被接受、工具能读哪些数据、一次任务最多走多少步、什么时候转人工，这些边界仍然由开发者定义。

几个常被混在一起的概念，可以先用下面的方式区分：

| 概念 | 执行路径由谁决定 | 初学时怎么判断 |
| --- | --- | --- |
| Chatbot | 用户下一句问什么 | 主要生成回答，不主动操作外部系统 |
| Workflow | 开发者预先编排 | 步骤基本固定，分支和顺序写得很清楚 |
| Agent | 模型在受限工具集内选择 | 路径可能变化，但有最大步数和停止条件 |
| RAG | 先检索，再交给模型生成 | 它解决知识来源问题，不一定构成 Agent |
| MCP | 客户端和工具服务之间的协议约定 | 它解决工具接入问题，不替代模型或框架 |

产品命名不必太较真。有些平台把固定工作流也称作 Agent，有些框架把单次工具调用包装成 Agent。对学习者更有用的问题是：路径由谁决定，工具有什么权限，状态存在哪里，失败后怎么办。

### 三条路线怎么选

**完全不想写代码**的人，可以先用 Coze 或 Dify 验证产品思路。重点是 Prompt、知识库、变量、插件或 HTTP 调用、工作流和发布。目标不是做很多 Bot，而是让一个助手在三组不同输入下都能稳定工作。平台能降低门槛，但数据治理、权限、响应速度和复杂业务接口仍然需要工程能力。

**愿意写代码、想做 AI 应用开发**的人，先学 Python、HTTP、JSON 和模型 API。入门阶段不需要先学 PyTorch，也不要求自己训练模型。先裸调一次 API，再手写工具调用循环，理解模型返回的参数如何被校验和执行。等你知道框架替你封装了什么，再去学 LangChain 或 LangGraph。

**已有 Java 后端基础**的人，不必抛弃现有技术栈重来。先把模型调用封装进 Spring Boot，再把工具、权限、审计和业务数据接起来。LangChain4j 或 Spring AI 适合在这个阶段进入。Java 在事务、并发、权限、日志和部署上的积累，放到 Agent 项目里仍然是优势。

转行不是把上一份工作归零。更现实的做法，是找到原有能力和 Agent 项目的连接点：前端转做对话界面和消息流，测试转做评测集和失败复现，后端转做工具服务、权限和可观测性。

### 八周最小路线

按每周 8 到 10 小时计算，可以先走这条线：

| 周次 | 做什么 | 留下什么证据 |
| --- | --- | --- |
| 第 1 周 | 跑通一次模型 API，记录模型名、Prompt、响应和耗时 | 请求脚本、原始响应、费用字段 |
| 第 2 周 | 做结构化输出和两三个只读工具 | JSON 参数、工具返回、参数错误日志 |
| 第 3 周 | 用本地 Markdown 或 PDF 做最小 RAG | 切分说明、检索结果、回答引用和错例 |
| 第 4 周 | 写 Agent 循环，限制最大步数和超时 | 每一步动作、停止原因、失败恢复 |
| 第 5 至 6 周 | 做一个小项目，准备 10 至 20 条测试输入 | README、测试样例、演示录屏 |
| 第 7 周 | 统计成功率、工具准确率、耗时和成本 | 评测表、成本记录、失败分类 |
| 第 8 周 | 加权限、日志、部署和说明 | 部署文档、风险边界、项目复盘 |

每周只投入 4 小时的上班族，把周期拉长到 12 至 16 周更合适。项目阶段不要压缩，因为没有项目证据，课程进度很难转化成求职材料。

第一周不用追求框架。选一个很窄的任务，例如“读取本地三份课程笔记，回答一个问题并给出文件名”。先用原生 SDK 或 HTTP 调模型，能稳定返回 JSON 后，再考虑引入框架。这个顺序会逼你先理解输入、输出、异常和成本，而不是把问题都交给封装。

## 拓展

### 先看概念，但别把旧课当现成答案

[微软 AI Agents for Beginners 中英版本](https://www.bilibili.com/video/BV18TZYY8EuJ)一共 11 集，约 129 分钟，覆盖 Agent 定义、框架选择、工具使用、Agentic RAG、规划、多 Agent 和部署。B 站版本是搬运翻译，代码和配套课程以 [Microsoft 官方仓库](https://github.com/microsoft/ai-agents-for-beginners)为准。它适合建立词汇表，不适合当作某一家框架的 API 教程。

[吴恩达《用于 LLM 应用程序开发的 LangChain》中英字幕](https://www.bilibili.com/video/BV1zu4y1Z7mc)只有 8 集、约 98 分钟，发布于 2023 年。它讲模型、Prompt、Memory、Chain、文档问答和 Agent，对“为什么要有这些组件”仍然有帮助。但代码和 API 明显偏旧，只看思路，不要把示例代码直接搬进 2026 年的项目。

这两套选一套就够了。先看概念的收益，是后面遇到 LangChain、LangGraph 或 Spring AI 时，知道它们解决的是同一类流程里的不同问题。

### 不写代码：Coze 和 Dify 选一套

[黑马程序员 Coze 智能体入门到项目实战](https://www.bilibili.com/video/BV12omoB4ExF)共 28 集、约 5.5 小时，2025 年 12 月发布。课程覆盖 Prompt、RAG、Function Calling、工作流和六个实战案例，适合先认识一个 Agent 产品从配置到发布的完整过程。

[黑马程序员 Dify 零基础入门](https://www.bilibili.com/video/BV116w5zuEbo)共 29 集、约 4.4 小时，2026 年 3 月发布，内容延伸到 Dify 部署、本地模型、知识库、插件、工作流、Text2SQL、API 和前端对话界面，工程链条更完整。

选 Coze 或 Dify 其中一个，不要两边同时跟。真正要练的是把任务拆成“输入、知识、工具、输出、失败处理”，而不是记住某个平台按钮的位置。平台界面更新很快，跟课时记下版本和日期；配置成功也不代表系统可维护。

### 写代码：Python 和 LangChain 路线

如果目标是 AI 应用开发，[黑马程序员大模型 RAG 与 Agent 智能体项目实战](https://www.bilibili.com/video/BV1yjz5BLEoY)可以作为第一门系统课。它共 67 集、约 15.5 小时，2026 年 1 月发布，从云端模型和 Ollama 接入讲到提示词、RAG、LangChain 和项目实战。课程时长可控，适合边看边做。

想跟更近期、更细的 LangChain 内容，可以看[尚硅谷 2026 版 LangChain 教程](https://www.bilibili.com/video/BV1rv7A6oEeP)。它共 120 集、约 21.4 小时，2026 年 6 月发布，内容覆盖模型调用、工具、Agent、中间件、记忆、RAG 和综合项目。课程很完整，也很容易让人产生“看完就会”的错觉。更合理的使用方式是先跑通前几章，把后面的章节当工具书查。

两门课不要线性看两遍。主线以一门为主，遇到 API 变化、依赖冲突或框架概念不清，再去另一门课和官方文档交叉核对。LangChain 的接口变化不慢，课程标题写着“最新”，仍然要固定依赖版本，并把版本写进 `requirements.txt`。

### Java 后端：LangChain4j、Spring AI 和 MCP

有 Spring Boot 基础的人，可以先看[黑马程序员 LangChain4j 入门到实战](https://www.bilibili.com/video/BV1sDMqzpEQ3)。课程共 23 集、约 5.5 小时，2025 年 6 月发布，覆盖 Ollama、模型调用、会话记忆、Spring 整合、RAG 和志愿填报顾问项目。它比较适合从熟悉的 Java Web 结构进入 Agent。

想补底层细节，再看[尚硅谷 LangChain4j 教程](https://www.bilibili.com/video/BV1mX3NzrEu6)。它共 85 集、约 8.2 小时，2025 年 7 月发布，对框架分层、模型接入和各类组件讲得更细。两门课内容重叠，选一门主课即可，另一门用来查缺。

Spring AI 更适合已经能读懂 Spring Boot 配置和依赖管理的人。可以从[Spring AI 官方文档](https://docs.spring.io/spring-ai/reference/)开始，再用项目验证模型客户端、工具调用、RAG、可观测性和版本兼容性。B 站上也有体量较大的 Spring AI 系列课程，但“唯一最好”“全网最细”属于标题宣传，进入项目前仍要核对官方文档和实际依赖。

MCP 不要一开始就啃协议细节。先看[尚硅谷 MCP 实战指南](https://www.bilibili.com/video/BV1eK5DzHEWu)，约 2 小时，里面演示了 Cursor、Cline 以及 Java、Spring AI、LangChain、LangChain4j 等接入方式。看完之后回到 [MCP 官方入门文档](https://modelcontextprotocol.io/introduction)，核对客户端、服务端、资源和工具这些概念。MCP 解决的是工具接入和复用，不是让普通聊天模型自动变聪明。

### 官方资料放在旁边查

下面这些链接不适合从头背，但应该在项目里反复使用：

- [Hugging Face Agents Course](https://huggingface.co/learn/agents-course/unit0/introduction)：免费课程，概念、工具、Agent 和评测结构比较完整。
- [OpenAI Agents SDK](https://openai.github.io/openai-agents-python/)：查看 Agent、工具、handoff 和 tracing 的当前实现。
- [LangChain](https://python.langchain.com/docs/introduction/)与 [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview)：先看当前版本，再决定是否真的需要引入。
- [Model Context Protocol](https://modelcontextprotocol.io/introduction)：MCP 的协议、服务器和客户端说明。
- [Spring AI](https://docs.spring.io/spring-ai/reference/)与 [LangChain4j](https://docs.langchain4j.dev/)：Java 项目需要以这两个官方入口为准。

B 站课程的播放量和收藏量只能说明关注度，不能替代内容质量判断。选课时至少看三件事：课程有没有完整项目、是否展示失败和调试、代码仓库或资料是否还能访问。只有演示成功、从不处理异常和成本的长课，后面大概率会让你自己补瀑布式的问题。

### 学习方法：视频不是进度条

我建议的规则很简单：每看 20 至 30 分钟，立刻停下来写一个最小版本。不要一开始就手敲课程里的完整项目，先只复现当前这一小段能力。例如课程讲到工具调用，就只做一个“查天气”或“查本地文件”的函数，打印模型返回的参数，再手动执行。

每跑完一个最小例子，回答三个问题：

1. 模型为什么选择这个工具，是提示词、工具描述还是上下文造成的？
2. 状态保存在哪里，关掉程序后还剩什么？
3. 什么情况下流程会停止，是成功、超时、达到最大步数，还是需要人工接管？

这三个问题比背框架 API 更耐用。它们也会暴露课程里没说清的部分。遇到代码不能运行，先记录依赖版本、完整报错和已经排除的可能，再查官方文档、GitHub Issue 和源码。只截图报错发群里，很难形成自己的排查能力。

准备一个失败日志，格式可以很土，但必须能复盘：

```text
日期：
目标：
模型与版本：
输入：
调用步骤：
错误信息：
怀疑原因：
验证方式：
修正结果：
仍未确定：
```

项目做多了以后，这份日志比“课程已看完”更能证明你会解决问题。

### 第一个项目怎么选

项目不需要大，先从单目标、低风险、可验证的任务开始。下面三个方向都适合入门，但不要同时做。

**知识库问答助手。** 输入是 10 至 30 篇本地 Markdown 或 PDF，输出必须带文件名和段落引用。重点练切分、检索、引用和拒答。测试时故意问一个资料里没有的问题，观察它会不会编答案。

**GitHub Issue 分类助手。** 输入是 Issue 标题和正文，输出是类型、优先级、缺失信息和回复草稿。第一版只允许读取，不允许自动评论。等分类准确率稳定后，再把“发送回复”做成人工确认动作。

**Java 内部知识库 Agent。** 用 Spring Boot 暴露一个简单接口，把模型客户端、检索服务、工具服务和审计日志分开。它不追求界面复杂，重点是把工具权限、超时、重试、日志和接口错误处理做完整。

写项目说明时，把下面这些字段补齐，比堆十篇“AI 大神进阶”文章更有用：

```text
项目名：
目标用户：
输入和输出：
允许使用的工具：
状态保存在哪里：
停止条件：
人工确认点：
失败示例：
评测样例：
成本和延迟：
已知限制：
```

### 评测和边界不能等到最后

Agent 的非确定性很高，拿两次成功对话当结论没有说服力。项目一开始就准备 10 至 20 条测试输入，分别覆盖正常问题、边界问题、工具失败、检索不到、危险操作和超时。

最低限度记录这些指标：

- 任务完成率：多少条输入真正完成了目标。
- 工具调用准确率：是否调用了正确工具，参数是否正确。
- 引用命中率：RAG 场景中有没有给出来源，来源能不能支持答案。
- 平均步骤、延迟和 token 成本：Agent 多走几步，费用和等待都会累加。
- 失败类型：模型不会、工具报错、检索错误、权限拦截或代码异常。

权限要从第一天设计。读取文件、查询数据库和发送邮件看起来都是“工具”，风险完全不同。写入、删除、发送、支付和修改线上配置这类动作，第一版都应该加人工确认。API Key 放进环境变量或密钥管理服务，客户端侧不要暴露服务端密钥。再加最大步数、超时、重试上限和基础限流，否则一个循环错误就可能把预算烧完。

### 新手最容易掉进去的几个坑

**一上来就学多 Agent。** 大多数入门项目用单 Agent 加固定 Workflow 就能完成。多 Agent 会引入额外通信、状态同步和评测复杂度，先证明单 Agent 确实不够，再考虑。

**只收藏，不动手。** 收藏二十门课不会提高能力。一门主课跟到第一个项目，再决定要不要换。

**频繁换框架。** LangChain、LangGraph、Spring AI、LangChain4j 解决的是不同层面的问题。你连工具参数为什么错都看不出来，换框架只会换一种报错。

**把 RAG 当成上传文件。** 切分太大、检索不到、引用不准、资料过期都会让回答看起来流畅但不可靠。RAG 要准备错例，不要只看演示问题。

**没有失败恢复。** 真实用户会输入空内容、恶意指令、超长文本或要求做危险操作。没有拒答、人工接管和权限控制，项目只能停在演示阶段。

**忽略成本和延迟。** 一次任务多调几次模型，费用和等待会明显增加。每次运行记下模型、步数、耗时和 token，不要等账单出来才排查。

### 求职作品集应该展示什么

简历上写“熟悉 Agent 开发”意义有限。更能说明问题的是一个可复现项目：README 写清目标、架构、工具权限、运行方式和已知限制；仓库提供环境变量示例和测试样例；录一段三到五分钟的演示，展示两个成功案例、一个失败案例，以及系统如何处理失败。

如果项目来自课程，可以写“基于课程实现并重构”，不要改几个变量后说成自己的原创商业项目。面试官更愿意听你解释为什么选 Workflow 而不是 Agent、为什么这个工具必须人工确认、评测里哪一类问题最容易失败。能讲清边界，比堆功能更可信。

Agent 入门真正难的地方，不是记住更多框架名，而是把目标、模型、工具、状态、停止条件和评测连成一条能运行、能复盘、能展示的链路。先从一条最小链路开始，学得会慢一点，但每一步都算数。
