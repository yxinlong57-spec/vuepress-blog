Java 的 == 和 equals 到底有什么区别？用 String、Integer 和自定义对象一次讲清

快速认识

== 和 equals 不是“一个比较地址，一个比较内容”这么简单。

更准确的规则是：

  • 两边是基本类型时，== 比较值。
  • 两边是对象引用时，== 判断它们是否指向同一个对象。
  • equals 是一个方法。Object 里的默认实现就是引用比较，但 String、包装类等会重写它。
  • 自定义类如果只重写 equals、不重写 hashCode，放进 HashSet 或作为 HashMap 的 Key 时仍然可能出错。

ArrayList 和 LinkedList 怎么选？别只看“插入删除快慢”

环境：JDK 17.0.12，Windows 11。本文的列表实验只使用 JDK 标准库，已经在本机完成编译和两轮运行。

快速认识

如果业务代码没有非常明确的节点访问需求，默认先选 ArrayList。

ArrayList 底层是连续数组，按索引 get 很直接，顺序遍历的内存局部性也更好。代价是中间插入或删除通常会搬动后面的元素。

LinkedList 底层是双向链表。拿到某个节点以后，改前后指针确实是 O(1)，但按索引查找节点要先从头或尾走一遍，所以 get(index) 和 add(index, value) 在业务代码里往往没有想象中快。

BIO、NIO、AIO 到底差在哪？从阻塞方式到代码模型一次理清

示例环境：JDK 17.0.12，Windows 11。三个 TCP 回显示例只使用 JDK 标准库，均已在本地完成编译和回显验证。

很多人第一次背 BIO、NIO、AIO，记住的是三句话：

BIO 一连接一线程，NIO 用一个线程处理多个连接，AIO 是异步的，所以 AIO 最快。

这三句话有对有错。它们描述了三种常见使用方式，却把不同层面的概念混在了一起。

先给结论：

  • BIO 的典型模式，是一个线程在 accept、read 或 write 上等待到操作完成。
  • NIO 的核心，是通过 Channel、Buffer 和 Selector 获取一批连接的“就绪事件”，再用少量线程处理事件。
  • AIO 的核心，是提交 I/O 请求后立即返回，操作完成时由回调或 Future 通知应用。
